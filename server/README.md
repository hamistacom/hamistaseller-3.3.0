# هامیستا کلود — سرور مرکزی (فاز ۵-الف)

سرور مرکزی هامیستا سلر: حساب کاربران، **لایسنس آنلاین**، سهمیه، لاگ فعالیت، **ابربانک کسب‌وکارها**، اعلان‌ها، نسخه‌ی ایجنت و «سناریو»ها.

- یک فایل اجرایی روی لینوکس، پایگاه داده **SQLite** (یک فایل، بدون نصب سرور دیتابیس جدا، پشتیبان‌گیری آسان).
- API کامل برای برنامه ویندوز (`/api/v1/...`) و برای پنل مدیر (`/api/v1/admin/...`).
- **پنل مدیر، برنامه دسکتاپ است** (نسخه `--features issuer` هامیستا سلر)، نه صفحه وب. سرور رابط کاربری ندارد و فقط موتور پشت صحنه است. همین راهنما، با دستورهای قابل کپی و متن تنظیمات آماده، داخل پنل مدیر (صفحه «اتصال سرور») هم هست.

## ۱. نصب روی سرور مجازی ایران (اوبونتو ۲۲/۲۴)

### الف) ساخت فایل اجرایی

روی یک سیستم با Rust (ویندوز خودتان یا همین سرور):

```bash
# نصب Rust (یک بار)
curl https://sh.rustup.rs -sSf | sh -s -- -y
source "$HOME/.cargo/env"

cd hamista-cloud
cargo build --release
# خروجی: target/release/hamista-cloud  (یک فایل مستقل)
```

روی سرور، فقط اگر خودتان آنجا build می‌کنید، این بسته‌ها لازم است:

```bash
sudo apt update && sudo apt install -y build-essential
```

> SQLite به صورت bundled کامپایل می‌شود؛ نیازی به نصب SQLite جدا نیست.

### ب) نصب فایل و پوشه داده

```bash
sudo useradd --system --home /opt/hamista hamista
sudo mkdir -p /opt/hamista/data
sudo cp target/release/hamista-cloud /opt/hamista/
sudo chown -R hamista:hamista /opt/hamista
sudo chmod 700 /opt/hamista/data          # پوشه داده فقط برای سرویس
```

### ج) تنظیمات (فایل محیط)

`sudo nano /opt/hamista/hamista.env`:

```ini
HAMISTA_BIND=127.0.0.1:8080
HAMISTA_DATA_DIR=/opt/hamista/data
HAMISTA_TOKEN_TTL_HOURS=72
HAMISTA_ADMIN_USER=admin
HAMISTA_ADMIN_PASS=یک‌رمز‌قوی‌اینجا
HAMISTA_SIGNING_SEED=کلید-خصوصی-۶۴-کاراکتری-پنل-مدیر
HAMISTA_AGENT_MIN_VERSION=2.0.0
```

| متغیر | کار | پیش‌فرض |
|---|---|---|
| `HAMISTA_BIND` | آدرس و پورت گوش دادن (پشت Nginx: `127.0.0.1:8080`) | `0.0.0.0:8080` |
| `HAMISTA_DATA_DIR` | محل پایگاه داده و کلیدها | `./data` |
| `HAMISTA_TOKEN_TTL_HOURS` | عمر توکن لایسنس = حداکثر مهلت کار آفلاین مشتری | `72` |
| `HAMISTA_ADMIN_USER` / `_PASS` | حساب مدیر، فقط در اولین اجرا ساخته می‌شود | `admin` / رمز تصادفی |
| `HAMISTA_SIGNING_SEED` | **کلید خصوصی پنل مدیر** (پنل ← کلید و پشتیبان ← پشتیبان کلید خصوصی). با آن سرور همان کلیدی را به کار می‌برد که لایسنس‌های آفلاین را امضا می‌کند، پس یک `license.pub` برای هر دو کافی است. فقط در این فایل نگه داشته می‌شود، نه در پایگاه داده. | (خالی = کلید جدا، توصیه نمی‌شود) |
| `HAMISTA_AGENT_MIN_VERSION` | حداقل نسخه مجاز ایجنت | `1.0.0` |

```bash
sudo chmod 600 /opt/hamista/hamista.env   # کلید و رمز مدیر در این فایل است
```

### د) سرویس systemd

`sudo nano /etc/systemd/system/hamista-cloud.service`:

```ini
[Unit]
Description=Hamista Cloud
After=network.target

[Service]
User=hamista
WorkingDirectory=/opt/hamista
EnvironmentFile=/opt/hamista/hamista.env
ExecStart=/opt/hamista/hamista-cloud
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hamista-cloud
sudo systemctl status hamista-cloud
curl http://127.0.0.1:8080/health    # باید ok برگرداند
```

### ه) دامنه و HTTPS (Nginx)

```nginx
server {
    server_name api.hamista.ir;        # دامنه خودتان
    location / { proxy_pass http://127.0.0.1:8080; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header Host $host; }
}
```

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.hamista.ir
```

> سرور IP واقعی را از هدر `X-Forwarded-For` که Nginx می‌گذارد می‌خواند (برای لاگ‌ها و سقف دوره آزمایشی). حتماً `$remote_addr` بگذارید، نه `$proxy_add_x_forwarded_for`؛ وگرنه هر کسی می‌تواند IP خود را جعل کند.

### دوره آزمایشی رایگان

در پنل مدیر ← «پلن‌ها ← دوره آزمایشی»: روشن/خاموش، پلن (بدون دسترسی بانک جامع) و تعداد روز (۱ تا ۶۰). مشتری از «تنظیمات ← لایسنس ← حساب آنلاین ← دوره آزمایشی رایگان» با نام و موبایل درخواست می‌دهد. هر کامپیوتر و هر شماره فقط یک بار، و حداکثر ۵ دوره در روز از هر IP. مسیرها: `GET /api/v1/trial` (اطلاعات) و `POST /api/v1/auth/trial`.

## ۲. راه‌اندازی اولیه (یک بار)

اگر `HAMISTA_SIGNING_SEED` را گذاشته باشید (روش توصیه‌شده)، کلید همان کلید پنل است و فایل کلید ساخته نمی‌شود. بعد از اجرا، در پنل مدیر ← اتصال سرور، باید «همان کلید پنل» نمایش داده شود.

بدون آن، سرور در اولین اجرا این دو فایل را در پوشه داده می‌سازد (آن‌ها را جای امن نگه دارید و از سرور خارج پشتیبان بگیرید):

| فایل | محتوا |
|---|---|
| `data/signing-key.txt` | **کلید امضا**. `public_key` را در فایل `src-tauri/license.pub` نسخه مشتری بگذارید و دوباره build کنید؛ `private_seed` روی سرور می‌ماند و مخفی است. |
| `data/admin-credentials.txt` | نام کاربری و رمز حساب مدیر (اگر در env نگذاشته باشید). |

> **کلید امضا قلب لایسنس است.** اگر گم شود، باید کلید تازه بسازید (پاک کردن `signing_seed` از دیتابیس) و نسخه مشتری را دوباره build و برای همه لایسنس‌ها صادر کنید. حتماً پشتیبان بگیرید.

### پشتیبان‌گیری

کل وضعیت در یک فایل است: `data/hamista-cloud.db` (و `-wal`/`-shm`). پشتیبان روزانه:

```bash
sqlite3 /opt/hamista/data/hamista-cloud.db ".backup '/opt/hamista/backup-$(date +%F).db'"
```

## ۳. جریان کار لایسنس (چطور از دور زدن جلوگیری می‌شود)

```
مشتری (ویندوز)                         سرور هامیستا کلود
 ├─ ورود با نام کاربری/رمز + کد سیستم ──►  بررسی رمز، سقف دستگاه، اشتراک
 │                                         ◄── توکن امضاشده (Ed25519) با عمر ۷۲ ساعت
 │                                             شامل: کاربر، کد سیستم، پلن، منابع مجاز،
 │                                             سهمیه باقی‌مانده، بله/خیر ابربانک
 ├─ هر چند ساعت: «ضربان» ───────────────►  صدور توکن تازه؛ اعمال تعلیق/باطل‌سازی
 ├─ قبل از هر استخراج/ارسال: مصرف سهمیه ─►  شمارش در سرور (اتمیک، غیرقابل دور زدن)
 └─ بین ضربان‌ها: بررسی آفلاین امضای توکن با کلید عمومی داخل برنامه
```

- **زمان را سرور تعیین می‌کند**، نه ساعت ویندوز.
- توکن فقط برای همان **کد سیستم** کار می‌کند؛ کپی روی کامپیوتر دیگر بی‌فایده است.
- **تعلیق/باطل‌سازی** از پنل مدیر، در اولین ضربان (حداکثر ۷۲ ساعت) اعمال می‌شود.
- **سهمیه‌ها** در سرور شمرده می‌شوند و با یک UPDATE اتمیک حتی در درخواست‌های هم‌زمان قابل تخطی نیستند. اگر مصرفی که بعد از کار گزارش می‌شود (مثلاً پیام‌های یک کمپین) از سقف بگذرد، سهمیه تا سقف پر می‌شود و کمپین بعدی رد می‌شود.
- **کار بدون اینترنت:** مصرف در این مدت در برنامه نگه داشته می‌شود و در همگام‌سازی بعدی شمرده می‌شود.
- **امنیت ورود مدیر:** بعد از ۱۰ تلاش ناموفق از یک IP، تا ۱۵ دقیقه ورود بسته می‌شود. برنامه‌ها فقط با `https://` وصل می‌شوند (به‌جز `127.0.0.1` برای آزمایش).
- اگر اینترنت قطع شود، مشتری تا پایان عمر توکن (۷۲ ساعت) کار می‌کند و بعد باید دوباره وصل شود.

## ۴. فهرست API

### برنامه مشتری (`/api/v1`)
| متد | مسیر | کار |
|---|---|---|
| POST | `/auth/login` | ورود؛ ثبت دستگاه؛ صدور توکن |
| POST | `/license/heartbeat` | ضربان؛ توکن تازه (Bearer) |
| POST | `/quota/consume` | مصرف سهمیه `{kind:scan|send, n}` |
| POST | `/megabank/ingest` | ارسال کسب‌وکارهای عمومی به ابربانک |
| POST | `/megabank/search` | جستجوی ابربانک (اگر پلن اجازه دهد) |
| GET | `/notifications` · POST `/notifications/read` | اعلان‌ها |
| GET | `/agent/version` | آخرین نسخه ایجنت (عمومی) |
| GET | `/scenarios/:source` | سناریوی استخراج هر منبع (عمومی) |

### پنل مدیر (`/api/v1/admin`, هدر `x-admin-token`)
`login` · `overview` · `plans` (+`/:id`) · `users` (+`/:id`, `/:id/devices`) · `devices/:id/revoke` · `logs` · `megabank/search|facets|export` · `notifications` · `version` · `scenarios` (+`/:source`) · `optouts`

> نمونه‌ی کامل درخواست‌ها در `tests/api.rs` است.

## ۵. معماری ماژولار منابع

منبع استخراج (`maps`, `neshan`, `balad`, `instagram`, `telegram`, …) در سرور فقط یک **مقدار** است: ستون `source` در ابربانک و یک ردیف در جدول `scenarios`. افزودن منبع جدید در آینده **نیازی به تغییر طرح دیتابیس ندارد**؛ کافی است ایجنت آن را بفرستد و در صورت نیاز سناریوی آن را از پنل مدیر منتشر کنید. موتور استخراج در سمت برنامه ویندوز هم ماژولار است (هر منبع یک ماژول).

## ۶. کنترل کیفیت این فاز

- کل سرور برای لینوکس بدون خطا و بدون هشدار کامپایل شد.
- **تست با برنامه واقعی:** در فاز ۵ (مدل ترکیبی)، همین سرور داخل تست‌های هامیستا سلر (`tests-harness/tests/cloud.rs`) اجرا و پنل مدیر و نسخه مشتری واقعی به آن وصل شدند.
- **تست سرتاسری واقعی** (`tests/api.rs`) روی همان روتر، احراز هویت، دیتابیس و امضای لایسنس که سرور زنده استفاده می‌کند: ورود مدیر و مشتری، بررسی و دستکاری‌ناپذیری امضای توکن، سقف دستگاه، ضربان، **سهمیه (۵ تا، ششمی رد)**، **تست هم‌زمانی: از ۲۰ درخواست هم‌زمان دقیقاً ۵ تا موفق**، ارسال/ادغام/جستجوی ابربانک، تفکیک و خروجی CSV، **تعلیق و باطل‌سازی دستگاه از راه دور**، اعلان‌ها، نسخه و سناریو.
- **بازبینی امنیتی مستقل:** بدون SQL injection (همه مقادیر کاربر bind می‌شوند)، بدون دسترسی مشتری به مسیرهای مدیر، حریم ابربانک حفظ‌شده (فقط فیلدهای عمومی). سه مورد اصلاح شد: سهمیه اتمیک (مسابقه‌ی هم‌زمانی)، محدود کردن عدد ورودی سهمیه، و هم‌زمان‌سازی زمان پاسخ ورود برای جلوگیری از لو رفتن نام‌های کاربری.
